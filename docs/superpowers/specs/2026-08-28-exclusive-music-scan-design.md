# 专属录音自动识别 · 设计规格

> 日期：2026-08-28
>
> 状态：产品与技术设计已批准，等待规格文档复核
>
> 范围：Android 音乐页面只识别真实文件名以 `yyzm` 开头的本地音频

## 一、背景与目标

当前音乐功能通过 `on_audio_query.querySongs()` 查询设备媒体库中的全部音频，随后把所有具备播放 URI 的歌曲注入播放器。用户希望把音乐功能变成只属于两个人的专属歌单：自己录制歌曲后，只要把文件名设置为以 `yyzm` 开头，App 就能在下次打开音乐页面时自动识别；手机中的其他歌曲永远不会进入 App 歌单。

设计目标：

- 不要求用户在 App 内手动选择或导入文件。
- 不要求每次增加歌曲时重新构建 APK。
- 不复制音频，不额外占用一份存储空间。
- 使用真实文件名作为唯一识别依据，不依赖不可靠的媒体标题标签。
- 每次打开音乐页面自动刷新；新增、删除和改名结果自然反映到歌单。
- 保留现有播放器、迷你播放条、回忆照片封面、播放模式和进度控制。
- 减少对无关歌曲元数据和封面的读取，只处理候选文件及最终匹配项。

## 二、已确认的产品决策

| 项目 | 决策 |
| --- | --- |
| 歌曲来源 | Android 系统媒体库中的本地音频 |
| 识别方式 | 真实文件名去掉扩展名后以 `yyzm` 开头 |
| 大小写 | 不区分大小写，`yyzm`、`YYZM`、`Yyzm` 均匹配 |
| 自动刷新 | 每次打开音乐页面重新识别一次 |
| 页面内刷新 | 保留“重新识别”按钮，不做后台实时监听 |
| 文件保存 | 直接播放原文件 URI，不复制到 App 私有目录 |
| 文件变化 | 删除或取消前缀后，下次成功扫描时自动从歌单消失 |
| 展示名称 | 隐藏 `yyzm` 前缀，并清理紧随其后的空格、下划线和短横线 |
| 无有效名称 | 显示“未命名录音” |
| 无歌手标签 | 显示“专属录音” |
| 歌单名称 | “我们的歌” |
| 排序 | 系统添加时间倒序，最新录音优先；相同时间按媒体 ID 保持稳定 |
| 平台范围 | 第一版正式支持 Android，不承诺 iOS 真实文件名前缀行为 |
| 同步范围 | 歌曲不进入 Isar，不上传腾讯云，不参与双机同步 |

## 三、范围与非范围

### 3.1 第一版包含

- 使用 Android MediaStore 按显示文件名预筛选音频。
- 使用纯 Dart 规则进行严格前缀校验和展示名称清理。
- 只为最终匹配歌曲查询内嵌封面。
- 匹配歌曲映射为现有 `MusicSong`，注入现有播放器。
- 成功扫描后的歌单增删、重排和当前歌曲协调。
- 专属录音空状态、权限状态、扫描错误状态和重新识别入口。
- 播放列表标题及相关文案调整。
- 文件名规则、查询映射、播放器协调和页面状态测试。

### 3.2 第一版不包含

- App 内录音、剪辑、重命名或音频标签编辑。
- 文件选择器、手动导入或目录授权流程。
- 将音频复制到 App 沙盒或生成冗余备份。
- 后台文件监听、定时扫描或系统媒体变化广播监听。
- 用户可配置的文件名前缀。
- 歌曲数据库、收藏、歌词或封面编辑。
- 音频文件、播放记录或歌单的云端同步。
- 播放器主体布局重构。
- iOS 本地文件名前缀识别承诺。

## 四、识别与展示规则

### 4.1 匹配输入

识别必须使用 MediaStore 提供的真实显示文件名，而不是音频内部的 `title` 标签。判断时先去除最后一个文件扩展名，再执行大小写无关的前缀检查。

严格规则：

```text
displayNameWithoutExtension.toLowerCase().startsWith("yyzm")
```

`yyzm` 必须位于文件名开头；仅在中间或结尾出现时不匹配。

### 4.2 展示名称清理

匹配成功后按顺序处理：

1. 去掉开头四个字符 `yyzm`，保留原文件名其余部分。
2. 连续去掉紧随其后的空白字符、半角或全角下划线、半角或全角短横线。
3. 对剩余文本执行首尾空白清理。
4. 如果结果为空，使用“未命名录音”。

示例：

| 真实文件名 | 是否匹配 | App 显示名称 |
| --- | --- | --- |
| `yyzm_小幸运.m4a` | 是 | `小幸运` |
| `YYZM-第一次录给你.mp3` | 是 | `第一次录给你` |
| `yyzm 生日快乐.wav` | 是 | `生日快乐` |
| `yyzm晴天.flac` | 是 | `晴天` |
| `yyzm___晚安.m4a` | 是 | `晚安` |
| `yyzm.m4a` | 是 | `未命名录音` |
| `我的录音_yyzm.m4a` | 否 | 不显示 |
| `普通歌曲.mp3` | 否 | 不显示 |

### 4.3 元数据映射

匹配歌曲继续使用现有 `MusicSong` 内存模型：

```text
id          ← MediaStore 媒体 ID
title       ← 文件名规则生成的展示名称
artist      ← 有效媒体歌手标签；缺失、空白或系统未知值时使用“专属录音”
duration    ← MediaStore 时长
uri         ← MediaStore content URI
coverIndex  ← 媒体 ID 对现有渐变数量取模
coverBytes  ← 匹配后按批次查询的内嵌封面；失败时为 null
```

文件无有效 URI 时不得进入歌单。单首封面读取失败不能阻断该歌曲或整次扫描。

## 五、查询架构

### 5.1 两阶段筛选

第一阶段由 Android MediaStore 预筛选：

```text
DISPLAY_NAME LIKE "%yyzm%"
```

当前 `on_audio_query` 的 `queryWithFilters` 只支持包含查询，因此它只能减少候选集合，不能承担最终规则判断。

第二阶段在 Dart 中调用文件名规则，对候选集合执行严格 `startsWith` 校验。只有第二阶段通过的歌曲才能查询封面并进入播放器。

这保证：

- 文件名中间出现 `yyzm` 的音频不会误入歌单。
- 不再对整个设备歌曲列表逐首查询封面。
- 最终业务规则不依赖插件内部 SQL 的大小写或匹配细节。

### 5.2 查询抽象

新增可替换的 `MusicLibrarySource`，负责平台调用：

```text
requestPermission()
queryByDisplayName(String candidate)
queryArtwork(int songId)
```

生产实现 `OnAudioQueryMusicLibrarySource` 封装 `OnAudioQuery`；测试通过 Provider 注入 Fake Source。`musicLibraryProvider` 不再直接实例化平台插件。

建议文件结构：

```text
love_space/lib/features/music/
├── models/
│   ├── music_song.dart
│   └── music_filename_policy.dart
└── providers/
    ├── music_library_source.dart
    └── music_library_provider.dart
```

职责边界：

- `MusicFilenamePolicy`：纯函数匹配和标题清理，不访问平台。
- `MusicLibrarySource`：权限、MediaStore 查询和封面读取，不包含业务筛选规则。
- `musicLibraryProvider`：编排权限、预筛选、严格过滤、排序、封面批处理和模型映射。
- `MusicPlayerController`：协调新歌单与正在播放的歌曲，不理解文件名前缀。

### 5.3 排序

最终匹配歌曲按 MediaStore `dateAdded` 倒序排列；没有添加时间时视为最早。添加时间相同时按媒体 ID 倒序排列，确保多次扫描顺序稳定。排序发生在封面读取前，封面批处理必须保持输入顺序。

## 六、页面触发与数据流

音乐库改为 `FutureProvider.autoDispose`。音乐页首次创建时继续通过 `ref.listenManual` 触发 `musicLibraryProvider`；页面关闭且监听者释放后，缓存的扫描结果随 Provider 一起释放，因此下次重新打开页面会创建新的扫描任务。“重新识别”按钮显式调用 `ref.refresh`，在当前页面内立即重新扫描。

完整数据流：

```text
打开 MusicPlayerPage
  → musicLibraryProvider
  → MusicLibrarySource.requestPermission
  → MediaStore 文件名候选查询
  → MusicFilenamePolicy 严格过滤与清理
  → 对匹配歌曲批量查询封面
  → 排序并生成 List<MusicSong>
  → MusicPlayerController.reconcilePlaylist
  → 播放页面、我们的歌弹层与迷你播放条
```

只有成功返回的扫描结果可以改变播放器歌单。加载中或平台异常不能把旧歌单误判为空。

## 七、歌单与播放状态协调

当前页面在扫描结果为空时直接返回，可能让旧歌单继续残留。本次必须让成功的空列表进入播放器协调逻辑。

播放器新增异步的歌单协调入口，名称可采用 `reconcilePlaylist(List<MusicSong>)`。具体行为固定如下。

### 7.1 当前歌曲仍在新歌单中

- 按媒体 ID 重定位新索引。
- 保留已加载歌曲身份。
- 保留播放或暂停状态。
- 保留播放进度。
- 不调用 `setUrl`，不重载音源。
- 新增、删除或重排其他歌曲不打断当前歌曲。

### 7.2 当前歌曲不在新歌单中

- 使所有在途切歌请求失效。
- 调用音频后端 `stop()`，停止旧音源并将位置归零。
- 清除已加载歌曲身份、加载态和旧时长。
- 如果新歌单非空，选中第一首可播放歌曲，但不自动播放。
- 如果新歌单为空，将 `currentIndex` 设为 `-1` 并隐藏迷你播放条。

`AudioBackend`、`JustAudioBackend` 和测试 Fake 必须新增 `stop()`，避免仅 `pause()` 后仍保留已经从专属歌单移除的旧音源。

### 7.3 从未选择歌曲

- 新歌单非空时沿用现有行为：选中第一首可播放歌曲，但不自动播放。
- 新歌单为空时保持无选中状态。

### 7.4 扫描失败

- 权限拒绝或平台查询异常均不调用歌单协调入口。
- 已存在的播放器状态不因临时错误被清空。
- 页面显示错误与“重新识别”入口。

## 八、界面与文案

播放器主体布局不变。

### 8.1 播放列表

弹层标题从：

```text
播放列表（N 首）
```

改为：

```text
我们的歌（N 首）
```

弹层空文案改为“还没有找到专属录音”。

### 8.2 空状态

标题：

```text
还没有找到我们的歌
```

说明：

```text
请将录音文件名改为以 yyzm 开头，
例如 yyzm_小幸运.m4a，
然后重新打开音乐页面。
```

操作按钮：

```text
重新识别
```

### 8.3 权限状态

标题保持“需要音乐和音频权限”。说明改为：

```text
授权后，App 才能自动识别以 yyzm 开头的专属录音。
其他歌曲不会加入“我们的歌”。
```

操作按钮改为“允许访问”。Android 系统权限仍为设备级音频读取权限；App 业务层只处理匹配歌曲。

### 8.4 扫描错误

平台调用失败显示：

```text
识别歌曲失败，请重试
```

并提供“重新识别”。扫描失败必须与成功但无匹配歌曲区分。

## 九、权限、隐私与平台限制

- Android 13 及以上继续声明并请求 `READ_MEDIA_AUDIO`。
- Android 12 及以下继续使用受最大 SDK 限制的 `READ_EXTERNAL_STORAGE`。
- 不新增文件选择器或存储权限依赖。
- Android 系统权限是设备音频库级别，无法在权限弹窗中限制为 `yyzm` 文件。
- App 的 MediaStore 查询先按 `yyzm` 候选条件过滤，业务层只为严格匹配歌曲加载封面和构建模型。
- 音频文件不进入 App 数据库、腾讯云同步、Git 仓库或日志。
- 日志不得输出完整本地文件路径或 URI；错误日志只记录异常类型和必要上下文。
- 第一版不改变 iOS 行为，也不把 iOS 文件名前缀识别列为验收项。

## 十、错误与边界处理

| 场景 | 处理 |
| --- | --- |
| 权限拒绝 | 抛 `MusicPermissionDeniedException`，不改动旧播放器状态，显示专属权限说明和允许访问按钮 |
| MediaStore 查询异常 | 抛专用扫描异常，保留旧播放器状态，显示重新识别 |
| 候选结果为空 | 成功返回空列表，清空旧专属歌单并进入空状态 |
| 候选只在中间包含 `yyzm` | Dart 严格规则过滤，不查询封面 |
| 文件无 URI | 丢弃该条目，不进入播放器 |
| 文件名仅为 `yyzm` | 标题回退为“未命名录音” |
| 歌手为空或系统未知 | 显示“专属录音” |
| 单首封面读取失败 | 保留歌曲，使用渐变封面 |
| 当前歌曲被删除或取消前缀 | 成功扫描后停止旧音源，选择新歌单第一首但不播放 |
| 当前歌曲仍存在 | 保持音源、进度和播放状态 |
| 单首播放 URI 失效 | 保留现有错误提示并尝试下一首 |
| 扫描期间页面关闭 | Provider 和监听按 Riverpod/页面生命周期释放，不更新已销毁页面 |

## 十一、测试设计

### 11.1 文件名规则测试

新增 `test/music/music_filename_policy_test.dart`：

- 小写、大写和混合大小写前缀均匹配。
- 文件名中间或结尾出现 `yyzm` 时不匹配。
- `mp3`、`m4a`、`wav`、`flac` 及大小写扩展名正确去除。
- 下划线、短横线、全角变体和空格正确清理。
- 多个连续分隔符正确清理。
- 仅有前缀或前缀加分隔符时回退为“未命名录音”。
- 文件名包含多个点时只去掉最后一个扩展名。

### 11.2 音乐库测试

新增 `test/music/music_library_provider_test.dart`，通过 Fake Source 验证：

- Provider 请求音频权限后才查询候选歌曲。
- 查询使用 `yyzm` 和显示文件名筛选类型。
- 只有严格前缀歌曲进入结果。
- 非匹配候选不会调用 `queryArtwork`。
- 无 URI 条目被过滤。
- 显示标题和默认歌手正确。
- 添加时间倒序与 ID 次级排序稳定。
- 封面失败只影响单首封面。
- 权限拒绝、扫描失败和成功空结果是三个不同状态。

### 11.3 播放器测试

扩展 `test/music/music_player_controller_test.dart`：

- 当前媒体 ID 仍存在时保留索引映射、播放进度和加载身份。
- 新增歌曲不调用 `stop` 或 `setUrl`，不打断当前播放。
- 当前歌曲消失时调用一次 `stop`，清除旧状态并选中第一首但不播放。
- 成功空歌单调用 `stop`、清空列表、设 `currentIndex = -1` 并隐藏迷你条。
- 从未选歌时非空歌单仍自动选中第一首但不播放。
- 在途加载在歌单替换后不能覆盖新状态。

### 11.4 Widget 与权限时机测试

- 空状态显示 `yyzm` 命名示例和“重新识别”。
- 权限状态显示专属录音说明和“允许访问”。
- 扫描错误显示错误文案，不显示无歌曲文案。
- 播放列表标题为“我们的歌（N 首）”。
- 点击重新识别刷新 Provider。
- App 启动和打开“我的”页仍不请求音频权限；只有打开音乐页才扫描。
- 成功空扫描会清除先前注入的测试歌单。

Android 真机验收准备四个文件：

```text

```

首次打开音乐页面后只能看到：

```text

```

随后把 `yyzm_小幸运.m4a` 改名为 `小幸运.m4a`，关闭并重新打开音乐页面：

- “小幸运”从歌单消失。
- “生日快乐”仍存在。

- 数百首普通歌曲存在时，App 仍只为匹配候选查询封面。
- 文件被删除或 URI 失效时，播放器给出明确反馈且不会卡在加载态。

## 十三、完成定义

以下条件全部满足才视为完成：

1. 音乐页面不再使用全量 `querySongs()` 作为业务歌单来源。
2. MediaStore 预筛选和 Dart 严格前缀过滤同时存在。
3. 所有最终展示歌曲的真实文件名都以 `yyzm` 开头，匹配不区分大小写。
4. App 标题隐藏前缀和分隔符，无名称时使用“未命名录音”。
5. 非匹配歌曲不进入模型、不查询封面、不出现在任何播放器界面。
6. 音乐库使用自动释放的 Provider；每次打开页面和点击重新识别都能启动新的扫描并刷新歌单。
7. 删除或取消前缀后，歌曲在下一次成功扫描中消失。
8. 当前歌曲消失时真正停止旧音源；仍存在时保留进度和播放状态。
9. 成功空列表、权限拒绝和扫描异常得到不同处理。
10. 现有播放器功能及权限请求时机无回归。
11. 文件名策略、查询层、播放器协调和页面状态有自动化测试覆盖。
12. 格式检查、静态分析、完整测试和 Android Debug APK 构建全部通过。
