# 公路闪避赛车小游戏 · 设计规格

> 日期：2026-08-26
> 状态：已批准；第一版已实现并通过验证
> 范围：在「小游戏」中心新增竖屏俯视角赛车躲避游戏，纯 Flutter Canvas 实现

## 一、背景与目标

「以越之名」当前已有打砖块和俄罗斯方块两款纯 Flutter 小游戏。本功能新增一款适合单手、随时开始、单局节奏紧凑的竖屏赛车游戏：玩家通过连续左右拖动赛车，躲避道路上的车辆和施工障碍，以行驶距离挑战本机最高纪录。

设计目标：

- 操作无需精准按住赛车，单手拖动即可控制。
- 画面清晰，三车道在高速阶段仍易辨识。
- 一次碰撞结束本局，规则简单直接。
- 速度持续提升，障碍组合按阶段增加难度。
- 所有随机障碍都经过安全路线约束，不生成理论上无解的组合。
- 沿用现有 Flutter `Ticker + CustomPainter` 架构，不引入 Flame 或其他游戏引擎。
- 核心规则与随机生成均可通过纯逻辑单元测试验证。

## 二、已确认的产品决策

| 项目 | 决策 |
| --- | --- |
| 屏幕方向 | 仅竖屏，离开页面后恢复 APP 原方向配置 |
| 操控方式 | 屏幕下半部分连续左右拖动，不按车道吸附 |
| 道路结构 | 透视三车道，两条黄色虚线严格均分可行驶路面 |
| 视觉方向 | 清新日间公路：蓝天、绿地、灰色道路、彩色车辆 |
| 碰撞规则 | 一次有效碰撞立即结束本局 |
| 计分方式 | 按当前速度累计行驶距离，单位为米 |
| 难度方式 | 连续提速 + 每 25 秒一个障碍阶段的混合式递增 |
| 障碍范围 | 普通车辆、路锥、短护栏、带预警的变道车辆 |
| 历史纪录 | 本机持久化最高距离，不参与双机同步 |
| 声音范围 | 第一版不加入音乐或引擎音效；保留视觉反馈和轻震 |
| 技术路线 | 纯 Flutter Canvas + Ticker + 独立可测试游戏逻辑 |

## 三、范围与非范围

### 第一版包含

- 准备、倒计时、游戏中、暂停、碰撞反馈和结算状态。
- 连续横向拖动、道路边界限制和轻量平滑。
- 行驶距离、当前阶段、本机最高纪录和新纪录提示。
- 五段障碍难度与连续速度曲线。
- 普通车辆、路锥、短护栏和带转向预警的变道车辆。
- 合法障碍模板、安全通道可达性检查和确定性随机测试。
- APP 前后台自动暂停、游戏中退出确认和方向恢复。
- 小游戏中心入口。

### 第一版不包含

- 赛车纵向移动、跳跃、加速按钮、刹车或氮气。
- 自动吸附车道或左右实体按键。
- 多条赛道、车辆选择、皮肤、商店或道具系统。
- 生命值、复活、护盾或碰撞后继续。
- 联机对战、排行榜、成就或双机同步。
- 背景音乐、引擎声、碰撞音效或音频设置。
- Flame 游戏引擎、物理引擎或外部美术资源包。

## 四、核心玩法循环

1. 玩家从小游戏中心点击「公路闪避」。
2. 页面显示准备遮罩、操作提示和历史最佳距离。
3. 点击「开始游戏」后进入 `3、2、1` 倒计时。
4. 倒计时期间允许调整赛车横向位置，但不生成可碰撞障碍。
5. 倒计时结束后开始累计时间和距离，并生成交通障碍。
6. 玩家在屏幕下半部分左右拖动，赛车仅横向移动。
7. 游戏速度平滑上升；每 25 秒提高障碍模板复杂度。
8. 赛车碰撞任意障碍后立刻停止计分和生成，播放短碰撞反馈。
9. 结算页显示本局距离、历史最佳和新纪录状态。
10. 玩家可以立即重开或返回小游戏中心。

## 五、操控与碰撞

### 5.1 拖动区域与映射

- 页面下方 45% 的区域可以发起拖动，不要求按住赛车本体。
- `onPanStart` 记录起始手指位置与起始赛车横坐标。
- `onPanUpdate` 使用手指相对横向位移更新目标位置，避免赛车瞬移到指尖。
- 手指纵向变化不改变赛车纵向位置。
- 赛车中心固定在游戏区域约 78% 高度处，使手指可停留在赛车下方并保留前方视野。
- 目标横坐标使用当前赛车高度处的道路宽度换算为 `0.0–1.0` 标准化道路坐标。
- 赛车横坐标始终限制在道路白色边界内，并为可见车身宽度预留边距。
- 使用轻量插值消除手抖；横向最大移动能力按每秒 2.4 个道路宽度计算，横跨整条道路最多约 0.42 秒。

### 5.2 显示、触摸与碰撞区域

三个区域独立处理：

- 显示区域：完整赛车美术尺寸。
- 触摸区域：整个屏幕下方 45%，远大于赛车本体。
- 碰撞区域：以赛车和障碍可见矩形中心为基准，宽、高分别缩放到 78%。

碰撞采用轴对齐矩形相交检测。绘制和碰撞必须调用同一个道路透视投影模块，禁止分别实现两套位置换算。

### 5.3 单次碰撞

- 碰撞成立的当前帧立即冻结距离、速度、障碍移动和随机生成。
- 进入约 420ms 的碰撞反馈状态：赛车短距离震动、屏幕红色闪光、系统轻震一次。
- 反馈完成后进入结算状态。
- 不提供生命、复活或继续机会。

## 六、计分与最高纪录

### 6.1 距离计算

距离由当前速度积分：

```text
distanceMeters += speedMetersPerSecond(elapsedTime) × dtSeconds
```

- 初始计分速度为 16 米/秒。
- 计分速度与道路滚动速度使用同一个速度进度因子。
- 125 秒时达到 33.6 米/秒上限。
- HUD 和结算页显示向下取整后的整数米数。
- 躲过障碍不额外加分，避免随机密度影响成绩公平性。
- 倒计时、暂停和碰撞反馈期间不增加距离。

### 6.2 历史纪录

- 使用 `shared_preferences` 保存整数最高距离。
- 存储键固定为 `racing_best_distance_v1`。
- 只有本局整数距离严格大于旧纪录时才写入。
- 写入成功后显示「新纪录」。
- 读取失败按 `0 m` 处理；保存失败不影响结算与重开，只使用 `debugPrint` 记录。
- 纪录仅保存在本机，不写入 Isar，不进入双人同步协议。

## 七、速度与难度曲线

### 7.1 连续速度

设游戏有效运行时间为 `t` 秒：

```text
progress = clamp(t / 125, 0, 1)
speedFactor = 1 + 1.1 × progress
roadSpeed = 0.42 × speedFactor 个游戏场高度/秒
distanceSpeed = 16 × speedFactor 米/秒
```

- 开局道路速度为 0.42 个游戏场高度/秒。
- 速度在前 125 秒线性、连续增长。
- 125 秒后道路速度固定为 0.882 个游戏场高度/秒，距离速度固定为 33.6 米/秒。
- 达到速度上限后，难度只通过模板选择、反应时间和动态车辆比例变化，不再无限提速。

### 7.2 障碍阶段

| 阶段 | 有效时间 | 新增能力 | 生成反应时间范围 |
| --- | --- | --- | --- |
| 1 · 熟悉操控 | 0–25 秒 | 单辆直行车 | 1.70–2.20 秒 |
| 2 · 路线选择 | 25–50 秒 | 双车错位、单组路锥、短护栏 | 1.45–1.90 秒 |
| 3 · 连续躲避 | 50–75 秒 | 车辆与施工障碍连续组合 | 1.25–1.70 秒 |
| 4 · 动态交通 | 75–100 秒 | 带预警的单辆变道车 | 1.05–1.50 秒 |
| 5 · 高速耐力 | 100 秒以后 | 全部模板、更高动态车辆权重 | 0.90–1.30 秒 |

「生成反应时间」指从一批新障碍进入有效视野到其到达玩家纵向位置的预计时间。生成纵向间距根据当前道路速度与抽取的反应时间共同计算，因此提速后不会仅因固定像素间距造成突然无解。

### 7.3 变道车辆

- 只在阶段 4 及以后出现。
- 变道前闪烁对应方向的转向灯 0.8 秒。
- 警示结束后用 0.65 秒完成一次横向变道。
- 变道过程中仍保持纵向移动。
- 目标车道和移动扫过区域都必须加入安全路线检查。
- 禁止连续横跨两条车道，禁止无预警变道。

## 八、障碍模板与公平性

### 8.1 障碍类型

- `straightCar`：沿当前道路横向位置直行的普通车辆。
- `laneChangingCar`：先显示转向灯，再移动到相邻车道。
- `cones`：多个窄碰撞体组成的路锥阵列。
- `barrier`：占用一段横向区域的短护栏。

玩家车辆为玫瑰红；障碍车辆使用蓝、黄、绿等高对比颜色；施工障碍使用橙色，但与黄色车道线保持明度和形状差异。

### 8.2 合法模板

第一版使用有限、可验证的模板集合：

- 单车占一条车道。
- 两车占两条车道，留一条完整通道。
- 单侧路锥收窄一条车道。
- 路锥从两侧形成中央窄通道。
- 短护栏占一条车道。
- 普通车辆与施工障碍错位组合。
- 单辆变道车与一个静态障碍组合。

每个模板声明一个或多个 `SafeCorridor`，以标准化道路横向区间表示可通过区域。

### 8.3 可达性检查

生成器保存上一批障碍之后仍然可达的横向区间集合，以及上一批障碍的预计通过时间。游戏开始时，可达集合由玩家当前横坐标和首批障碍的反应时间计算。候选模板只有同时满足以下条件才可生成：

1. 候选模板至少有一个安全区间宽于玩家碰撞宽度加 35% 安全余量。
2. 计算 `maxTravel = 2.4 × 两批障碍的通过时间差`；把上一批每个可达区间向左右各扩展 `maxTravel`，裁剪到 `0.0–1.0` 后与候选安全区间求交集。
3. 变道车辆的起点、终点和移动扫过区域不会封死所有可达区间。
4. 新障碍不会直接生成在玩家附近的不可反应区域。

只有至少一个交集非空时，候选模板才是可达的；这些非空交集成为下一批的可达区间集合。候选模板不合法时重新抽取；连续失败达到预设次数后回退到单车模板，禁止绕过安全校验强行生成。

## 九、视觉与界面

### 9.1 道路画面

- 蓝天位于远端背景，绿色草地位于道路两侧。
- 深灰道路使用透视梯形，从远端向近端展开。
- 两侧白色实线仅表示道路边界。
- 两条黄色虚线位于道路内部：远端位置为道路宽度的 1/3、2/3，近端位置同样为 1/3、2/3，保证透视下始终三等分。
- 黄色虚线向下滚动表现速度。
- 草地上少量树木、路牌等装饰同步滚动，但不参与碰撞。
- 高速阶段限制同时可见装饰数量，优先保证障碍辨识度。

### 9.2 HUD

- 左上：本局距离，例如 `286 m`。
- 顶部中央：当前阶段，例如「阶段 3 · 加速中」。
- 右上：历史最佳，例如「最佳 842 m」。
- 暂停按钮位于右上安全区域，与最高分信息保持可点击间距。
- HUD 使用高对比阴影或半透明底，不能遮挡主要躲避路线。

### 9.3 页面状态

`RacingStatus` 固定包含：

```text
ready → countdown → playing ⇄ paused → crashed → gameOver
```

- `ready`：标题、简短操作说明、最佳纪录和开始按钮。
- `countdown`：显示 3、2、1；允许移动赛车，不计分、不生成碰撞障碍。
- `playing`：显示 HUD 和游戏场，隐藏状态遮罩。
- `paused`：冻结全部游戏时间，显示继续和结束本局。
- `crashed`：播放 420ms 碰撞反馈，不接收拖动输入。
- `gameOver`：显示本局距离、历史最佳、新纪录状态、再来一局和返回小游戏。

### 9.4 生命周期与退出

- 进入页面时锁定 `DeviceOrientation.portraitUp`。
- 离开页面时恢复 `DeviceOrientation.values`。
- APP 进入后台或页面失去前台焦点时，如果正在游戏则自动暂停。
- 返回前台后保持暂停，必须由玩家主动继续。
- 游戏进行中点击返回时先暂停并显示结束本局确认。
- 准备和结算状态允许直接返回。
- 页面退出时停止并销毁 Ticker，禁止后台继续更新。

### 9.5 反馈

- 倒计时数字缩放或淡入。
- 阶段提升显示短暂提示，不中断游戏。
- 变道车辆显示 0.8 秒转向灯。
- 碰撞时显示红色闪光、赛车短震动和一次 `HapticFeedback`。
- 新纪录使用明显但简短的高亮提示。
- 第一版不播放任何游戏声音，不请求或抢占音频焦点。


现有文件修改范围限定为：

- `features/games/games_page.dart`：增加「公路闪避」入口。
- `data/providers/data_providers.dart`：增加最高分 Repository 与 FutureProvider。
- `test/widget_test.dart`：同步新增 Provider override，并保留现有 APP 冒烟测试。
- `app/theme/app_colors.dart`：仅在现有令牌不足时增加赛车专用颜色；页面和 Painter 禁止硬编码颜色。

Widget 文件不得超过项目规定的 300 行；页面只负责生命周期、输入和导航，游戏规则不得堆叠在 Widget 中。

### 10.2 职责

- `RacingPage`：Ticker、方向、生命周期、拖动、导航、Repository 调用。
- `RacingGameEngine`：状态机、时间、速度、距离、障碍更新、碰撞结果。
- `racing_model.dart`：状态、实体、枚举和难度配置。
- `RacingObstacleGenerator`：合法模板、随机选择、安全区间和可达性。
- `RacingGeometry`：道路透视、实体屏幕矩形和碰撞矩形投影。
- `RacingPainter`：只读状态并绘制，不修改游戏数据。
- `RacingHud`：距离、阶段、最佳纪录和暂停入口。
- `RacingStatusOverlay`：准备、倒计时、暂停、碰撞和结算 UI。
- `RacingScoreRepository`：读取最高距离、仅在更高时保存。

### 10.3 每帧更新顺序

```text
Ticker 真实时间差
  → 丢弃非正 dt；忽略大于 66ms 的异常帧
  → 更新有效游戏时间、速度、阶段和距离
  → 更新普通障碍纵向位置
  → 更新变道预警与横向动画
  → 清理离开屏幕的障碍
  → 根据反应时间判断是否生成下一批
  → 选择合法模板并执行安全路线校验
  → 使用统一投影结果检测碰撞
  → 通知 Painter 与 HUD 重绘
```

第一次 Ticker 回调仅建立时间基准，不推进游戏。暂停、恢复和重新开始时重置帧时间基准，避免补算停顿时间。

## 十一、Provider 与数据流

新增 Provider 统一放在 `data/providers/data_providers.dart`：

```text
racingScoreRepositoryProvider
racingBestDistanceProvider
```

数据流：

```text
RacingPage
  → ref.watch(racingBestDistanceProvider)
  → RacingScoreRepository
  → SharedPreferences
```

- `RacingPage` 必须处理最高分的加载、成功和失败状态。
- 失败状态使用 `0 m` 继续游戏，不阻断页面。
- 游戏结束时仅在新纪录条件成立时调用 Repository。
- 异步保存结束后必须检查 `context.mounted` 或 State 的 `mounted`。
- 用户反馈使用项目统一组件；不得直接使用 `ScaffoldMessenger`。

## 十二、错误与边界处理

- 游戏场尺寸为零或尚未完成布局时不推进碰撞与生成。
- `dt <= 0` 时跳过该帧；`dt > 66ms` 时丢弃该帧，防止后台恢复或卡顿造成穿透。
- 障碍生成多次拒绝后回退到已知安全的单车模板。
- 高分读取失败默认 0，高分保存失败不改变本局结果。
- HapticFeedback 不可用时静默跳过，不影响结算。
- 重复点击开始、继续或重新开始必须保持幂等，不得创建多个 Ticker。
- 碰撞后忽略拖动与暂停输入，直到结算状态。
- 退出确认期间保持暂停；取消退出后仍由玩家主动继续。
- 障碍对象离开屏幕后立即回收，避免长局内列表持续增长。

## 十三、测试计划

### 13.1 游戏引擎

- 完整状态转换：ready、countdown、playing、paused、crashed、gameOver。
- 倒计时不计分，游戏中正确计分，暂停与碰撞后停止计分。
- 速度单调增加并在 125 秒达到上限。
- 每 25 秒进入下一障碍阶段。
- 相同随机种子产生相同障碍序列。
- 异常 dt 不造成障碍穿透或距离跳增。
- 重开完整清空旧局状态。

### 13.2 障碍生成

- 各阶段只启用允许的模板。
- 所有模板至少保留一个足够宽的安全区间。
- 连续模板的安全区间在规定时间内可达。
- 变道车辆扫过区域纳入校验。
- 多阶段、多固定种子批量生成时不出现无解组合。
- 生成失败回退单车模板。
- 屏外障碍正确清理，活跃障碍数量受控。

### 13.3 几何与碰撞

- 两条黄色线在透视道路远端和近端均严格三等分。
- 标准化横坐标正确映射道路边界与车道中心。
- 不同屏幕尺寸上的逻辑位置一致。
- 玩家无法被拖出道路。
- 明显重叠判撞，视觉擦边但缩小碰撞盒不重叠时不判撞。
- 绘制矩形与碰撞矩形来自同一投影。

### 13.4 Repository

- 无纪录返回 0。
- 更高距离覆盖旧纪录。
- 更低或相等距离不覆盖。
- Repository 重建后仍可读取已保存纪录。
- 测试使用 SharedPreferences mock，不写真实偏好。
- `widget_test.dart` 为新增 Provider 提供稳定 override，避免 APP 冒烟测试访问真实偏好。

### 13.5 Widget 与导航

- 小游戏中心显示「公路闪避」。
- 点击入口打开 `RacingPage`。
- 准备页显示最佳纪录与开始按钮。
- 开始后进入倒计时。
- HUD 显示距离、阶段、最佳纪录和暂停入口。
- 暂停遮罩可继续或结束。
- 结算显示本局成绩、历史最佳、再来一局和返回。
- 横向拖动改变赛车横坐标但不改变纵坐标。
- 页面退出后无 Ticker 或方向恢复异常。
